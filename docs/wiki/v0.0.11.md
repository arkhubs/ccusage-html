# ccusage-html Wiki v0.0.11

## Version Goal

v0.0.11 adds report-level light mode support and makes the theme switch easier to find:

- Generated reports now support both dark and light color themes.
- The header includes a single icon-only theme toggle instead of text buttons.
- The toggle shows a sun icon in dark mode and a moon icon in light mode.
- The selected theme is saved in `localStorage` as `ccusage.theme`.
- Canvas chart grid lines, labels, and line-chart point fills now read from CSS variables so they update with the active theme.

## Why This Changed

The report was previously designed as a dark-only dashboard. That worked well for terminal-like usage reviews, but it made reports harder to read in bright environments, during screen sharing, or when printed from a browser.

The first theme switch used visible `Dark` and `Light` text labels. In practice, that control was too easy to miss in the header and added more words to an already dense report surface. The replacement is a compact icon button placed next to the report title.

## User-Facing Behavior

The top-right header button controls the active color theme:

- In dark mode, the button shows a sun icon and switches the report to light mode.
- In light mode, the button shows a moon icon and switches the report back to dark mode.
- The button has no visible text, but keeps accessible labels and browser tooltips.
- The choice persists across reloads for the same browser through `localStorage`.

The theme script runs before the embedded stylesheet is applied, so generated reports can apply the saved theme early and avoid a visible dark-to-light flash on load.

Existing generated HTML files are static snapshots. Users need to regenerate a report to see the new theme toggle in that report.

## Design Notes

The theme is implemented through CSS custom properties on `:root` and `:root[data-theme="light"]`. Dark mode remains the default so existing generated reports keep the same first-load visual direction unless a saved light preference exists.

The icon button is intentionally a single round control rather than a segmented switch:

- it is more visible in the report header;
- it avoids adding `Dark` and `Light` text to the UI;
- it keeps the toolbar footprint small on mobile;
- it follows the report's existing compact dashboard style.

The icon SVGs are embedded directly in `report.html` so the final report stays standalone and does not require external icon assets or network access.

## Implementation Notes

- `report.html` adds the early theme bootstrap script and the `#themeToggle` icon button.
- `report.css` adds light-mode variables, theme-aware component colors, and icon-toggle styling.
- `report-state.js` owns theme normalization, `localStorage` persistence, toggle label updates, and theme switching.
- `report-utils.js` adds `cssVar()` for reading active CSS custom properties from JavaScript.
- `report-charts.js` uses `cssVar()` for chart grid, label, empty-state, and point-fill colors.
- `report-init.js` initializes the theme toggle before the rest of the report is rendered.

The generated report remains a single self-contained HTML document.

## Verification

The joined frontend assets were checked with:

```powershell
$scriptNames = @('report-state.js','report-utils.js','report-filters.js','report-charts.js','report-sessions.js','report-summary.js','report-init.js')
$text = ($scriptNames | ForEach-Object { Get-Content -Raw (Join-Path 'scripts\ccusage_html_report\assets' $_) }) -join "`n`n"
$text | node --check
```

A temporary localhost preview report was also opened in the in-app browser. Smoke checks confirmed:

- the theme control renders as a 42px icon-only button;
- the button has no visible `Dark` or `Light` text;
- dark mode shows the sun icon;
- clicking the button switches to light mode and shows the moon icon;
- body, panel, text, chart-line, and chart-point CSS variables all change to the light palette;
- the canvas chart is still initialized after the theme code runs.

## Notes

- Light mode is report-side only; it does not change CLI behavior or generated archive structure.
- The theme preference is stored per browser profile, not inside the report archive data.
- Old report files can still be opened normally, but they will not gain the new toggle unless regenerated.
