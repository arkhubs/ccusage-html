# ccusage-html Wiki v0.0.13

## Version Goal

v0.0.13 makes tool calls in the session conversation drawer selectively expandable and adds readable tool results when transcript data contains them:

- Tool calls now render as compact bubbles by default instead of always showing every argument and output body.
- Each tool call can independently expand or collapse its call details.
- Tool results can be expanded or collapsed by clicking the tool bubble when a result is available.
- The `Show call` and `Show result` buttons update only the selected tool turn, so the drawer position stays stable.
- Rendered and raw conversation modes preserve tool expansion state across re-rendering.

## Why This Changed

v0.0.12 added compact `Tool` turns so Codex and Gemini transcripts could show tool context. That made conversations much more complete, but tool output could still be noisy in long sessions. Some command results, diffs, logs, and fetched pages are large enough to dominate the drawer and make the actual conversation harder to scan.

The transcript data also had two different tool-output shapes:

- newer structured events can expose a call event and a separate result event;
- older Codex transcript output may appear as a user-like message beginning with `Output:`.

The report needed a way to read those results when possible, while keeping the default view quiet and useful.

## User-Facing Behavior

In the Sessions detail drawer, tool turns now have two independently controlled sections:

- `Show call` expands the full call summary, including command, working directory, description, arguments, and status when available.
- `Show result` expands the returned output for that tool call when the transcript contains a result.

When a tool turn has a result, clicking the bubble toggles the result section. When it only has call details, clicking the bubble toggles the call details. The buttons remain available for explicit control.

Expansion is selective per visible tool turn. Opening one result does not open every other result in the conversation. The drawer keeps its scroll position anchored around the clicked tool turn, so large results do not unexpectedly throw the user to another part of the session.

The conversation render switch still behaves like before:

- `Raw` shows escaped pre-wrapped text.
- `Rendered` shows Markdown-style formatting.
- switching between the two modes keeps already expanded tool calls and results expanded.

Search now also includes `toolName` and `toolResult`, so a session can be found by text that only appears in a tool result.

## Transcript Result Extraction

`scripts/ccusage_html_report/transcripts.py` now keeps tool data more structured in each conversation turn:

- `toolName` stores the call name when available.
- `toolCallId` stores the call identifier when available.
- `toolResult` stores readable result text.
- `toolResultChars` stores the result length.
- `toolResultTime` stores the result timestamp when available.

Structured Codex events such as `function_call_output`, `tool_call_output`, and `custom_tool_call_output` are matched back to the most recent known tool call by call ID. When no call ID is available, results are only attached to an immediately preceding tool turn to avoid accidentally attaching normal user text to an unrelated older call.

For older transcript shapes, Codex messages that begin with `Output:` or contain the known topic/context wrapper followed by `Output:` are treated as tool results and folded into the preceding tool call when possible.

Gemini tool-call records now use the same `toolResult` shape when result-like fields are present inside the call object.

## Frontend State Model

The report frontend stores tool expansion state in memory:

- `state.expandedToolCalls` tracks expanded call detail sections.
- `state.expandedToolResults` tracks expanded result sections.

The key is built from the active session key and visible turn index, matching the same stable rendering model already used by the conversation drawer. This keeps expansion state local to a session and lets `render/raw` re-render the visible turns without losing which tool sections are open.

`report-sessions.js` now renders each tool turn as:

- a compact preview of the call;
- an optional full call section;
- an optional result section;
- buttons for toggling call and result sections;
- bubble click and keyboard handlers for the default expandable section.

`report.css` adds the compact tool-state styling, focus outline, result divider, result label, and shared `.hidden` utility used by the interaction updates.

## Implementation Notes

- `add_conversation_turn()` accepts an `extra` map so transcript providers can attach structured tool fields without duplicating turn creation logic.
- Tool result parsing is centralized through helper functions for call IDs, result text extraction, result attachment, and legacy `Output:` handling.
- Codex tool calls and tool outputs are parsed separately, then merged when possible.
- Gemini tool calls return structured tool-turn dictionaries instead of plain `(text, time)` tuples.
- The session search haystack now includes tool names and tool results.
- Tool toggle handlers update the existing DOM node instead of rebuilding the entire drawer.
- Tool toggling preserves visual position by measuring the clicked turn before and after expansion and adjusting the drawer scroll offset.
- The project development checklist marks the two tool-call expansion items complete.

## Notes

- Existing archived HTML reports are static. Regenerate a report to get selective tool-call expansion and tool-result reveal.
- Tool results may include private command output, file paths, diffs, or fetched content. This matches the existing transcript-enrichment privacy model: local transcript data is embedded when transcript enrichment is enabled.
- Very large tool results remain embedded in the standalone report data. The new UI makes them less visually disruptive, but it does not remove them from generated HTML.
