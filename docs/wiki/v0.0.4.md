# ccusage-html Wiki v0.0.4

## 版本目标

v0.0.4 聚焦 model 价格和 model 级 cost 补全：

- Model mix 卡片展示当前价格：Input、Output、Cache hit，来源可用时也展示 Cache write。
- 当 `ccusage` 的 model breakdown 只有 token、没有 model 级 cost 时，自动用当前价格估算 `costUSD`。
- Cost 图表、Model mix 和 session model 明细都可以消费补全后的 model cost。
- 保留价格来源说明，避免把 best-effort 当前价格误认为历史账单原文。

## 为什么之前会出现 `Cost n/a`

`ccusage` 的 JSON 经常在 bucket 或 totals 上提供总 `costUSD`，但 nested `models` / `modelBreakdowns` 里只提供 token 字段：

```json
{
  "costUSD": 43.719375,
  "models": {
    "gpt-5.5": {
      "inputTokens": 3526925,
      "outputTokens": 301129,
      "reasoningOutputTokens": 112297,
      "cacheReadTokens": 34101760
    }
  }
}
```

前端的 Model mix 是按 `bucket.models[model].costUSD` 汇总的。旧版本没有 model 级 cost 时只能显示 `n/a`。

## v0.0.4 的处理方式

### 价格来源

生成 report data 时会按顺序尝试：

1. `https://models.dev/api.json`
2. `https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`

匹配策略：

- 优先精确匹配 model name。
- 再做大小写无关匹配。
- 再尝试 provider 前缀后的 suffix 匹配，例如 `openrouter/openai/gpt-5.4` -> `gpt-5.4`。

如果两个来源都不可用，报告仍会生成，只在 UI 中显示 price unavailable。

### Cost 估算公式

单位为 USD per 1M tokens：

```text
costUSD =
  inputTokens * inputPrice / 1_000_000
  + outputTokens * outputPrice / 1_000_000
  + cacheCreationTokens * cacheWritePrice / 1_000_000
  + cacheReadTokens * cacheHitPrice / 1_000_000
```

`reasoningOutputTokens` 不单独计费。用真实 `ccusage` 样本核对时，`ccusage` 的 cost 与 input + output + cache read 对齐，reasoning 字段没有作为独立价格项重复加入。

补全的 cost 会带上：

```json
{
  "costSource": "estimatedFromModelPrice"
}
```

## UI 变化

Model mix 卡片现在包含两层信息：

- Usage/cost totals：Total、Input、Output、Reasoning、Context、Cost。
- Current price：Input、Output、Cache hit、Cache write。

底部说明会提示：

- 价格是 best-effort current rates。
- model 级 cost 在 `ccusage` 未提供时由当前价格估算。
- 价格单位是 USD per 1M tokens。

## 注意事项

- 估算使用生成报告时的当前价格，不保证等同于历史账单的实际计费价格。
- 如果某个 model 有非零 token，但对应价格字段缺失，则该 model 的 cost 仍会显示 `n/a`。
- `--no-cost` 仍会尊重用户意图，不做 cost 补全。
