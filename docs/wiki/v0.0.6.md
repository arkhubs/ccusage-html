# ccusage-html Wiki v0.0.6

## Version Goal

v0.0.6 makes interactive preview startup reliable and fast:

- `--serve` starts the HTTP server before ccusage data collection.
- The command prints `Report URL` immediately.
- The first page is an auto-refreshing loading page that is replaced by the final dashboard.
- Busy fixed ports fall back to a free port unless `--strict-port` is used.
- The serving URL is no longer blocked by external model price fetches because the server starts before report generation.

## Why This Changed

The previous flow collected all ccusage data, fetched optional model prices, rendered the report, and only then started the HTTP server. That made the URL appear late. In Codex or other sandboxed command runners, the process could also be killed by a timeout before or shortly after the user clicked the URL.

The new flow reserves the port and starts serving first, so the user gets a reachable local URL quickly. The server still has to stay alive for the URL to work; the generated `Report HTML` file remains the durable fallback.

## Recommended Commands

```powershell
uv run python .\scripts\generate_ccusage_report.py all --serve --port 0
```

Fastest preview without transcript enrichment:

```powershell
uv run python .\scripts\generate_ccusage_report.py all --serve --port 0 --no-transcript
```

Fixed-port mode that fails when the port is busy:

```powershell
uv run python .\scripts\generate_ccusage_report.py all --serve --port 8765 --strict-port
```

## Notes

- The HTTP URL works only while the `--serve` process is running.
- `--port 0` is the safest default for automation because it avoids stale port conflicts.
- v0.0.7 keeps `--offline` scoped to ccusage and adds `--no-price-fetch` for intentionally skipping HTML report price lookups.
- If a tool timeout stops the serving process, open the printed `Report HTML` path or launch the server from a persistent/background process.
