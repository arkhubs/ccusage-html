# ccusage-html Wiki v0.0.8

## Version Goal

v0.0.8 makes the Sessions tab behave like a real session browser instead of a static dump:

- Sessions now have a normalized `sortTime` and are initially sorted by real recent activity.
- The Sessions toolbar adds filters for agent, model, transcript availability, and date range.
- Search covers titles, agents, models, IDs, dates, snippets, and full embedded conversation text.
- Conversation details use incremental `Load more turns` rendering instead of drawing the whole transcript at once.
- Session list `Load more` appends additional cards/list rows without rebuilding the visible list.

## Why This Changed

The previous Sessions ordering was effectively fake for mixed-agent reports. Many records did not expose a top-level `lastActivity`, so the frontend fell back to the raw ccusage order. This made new Codex sessions appear below older or undated records and made the initial browser state feel unreliable.

Full Codex conversations also rendered all turns when a session was opened. Long sessions could create a heavy drawer, and loading more conversation context required repainting the whole detail panel instead of appending only the next turns.

## User-Facing Behavior

Opening the Sessions tab now starts with recent sessions first whenever a timestamp can be inferred from:

- top-level `lastActivity`;
- metadata `lastActivity`;
- timestamp/date fields;
- Codex-style `period`, `sessionId`, `directory`, or `sessionFile` path text;
- the latest embedded local Codex conversation turn.

Manual filters can be combined with chart-bar filters. The active filter pills show search text, chart bucket, agent, model, transcript state, and date range; `Clear filters` resets the whole session browser.

## Dynamic Loading

Conversation rendering now starts with the first 24 turns. Each `Load more turns` click appends the next batch into the existing `.conversation` container, updates the visible/remaining counts, and removes the button only after the full transcript has been appended. It does not re-run `renderSessionDrawer()` or refresh the whole report.

The session list uses the same append-first behavior. Its `Load more` button inserts the next 80 matching sessions into the current list and updates the count without rebuilding already visible cards or closing the selected session drawer.

## Implementation Notes

- `report.py` adds timestamp extraction helpers, `lastActivityAt`, `sortTime`, and server-side recent-first session ordering.
- `html.py` adds manual filter state, filter option setup, filter pills, `oldest` sorting, and append-only loaders.
- Unknown-time sessions remain visible but naturally sort after sessions with known activity in recent-first mode.
- Date filters intentionally exclude `Unknown` dates because they cannot be compared safely.

## Verification

The change was checked with Python bytecode compilation and generated-template JavaScript syntax parsing:

```powershell
uv run python -m py_compile scripts\generate_ccusage_report.py scripts\ccusage_html_report\app.py scripts\ccusage_html_report\ccusage.py scripts\ccusage_html_report\cli.py scripts\ccusage_html_report\html.py scripts\ccusage_html_report\report.py
```

The current archived raw data was also rebuilt through `build_report_data_from_payloads`; the first sessions sorted to the latest known Codex activity on `2026-06-12`, confirming the new recent-first ordering path.

## Notes

- Generated HTML still embeds private conversation content when transcript enrichment is enabled.
- Search over full conversations is useful but can be heavier on very large reports.
- Browser-level verification may require a persistent localhost server because `file://` access is blocked by the in-app browser policy and sandboxed port binding can be restricted.
