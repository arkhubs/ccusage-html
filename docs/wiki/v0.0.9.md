# ccusage-html Wiki v0.0.9

## Version Goal

v0.0.9 focuses on source-code maintainability. It splits the two largest files into smaller responsibility-oriented modules while keeping the generated report behavior unchanged:

- `html.py` no longer stores the entire HTML, CSS, and frontend JavaScript inside one Python string.
- The report shell, stylesheet, and frontend scripts now live under `scripts/ccusage_html_report/assets/`.
- The frontend JavaScript is split into state, utilities, filters, charts, sessions, summary, and initialization files.
- `report.py` is reduced to report-data assembly orchestration.
- Data normalization, pricing, date parsing, and session enrichment now live in dedicated Python modules.

## Why This Changed

The project was still small, but two files had become difficult to scan:

- `scripts/ccusage_html_report/html.py` mixed Python rendering, HTML markup, CSS, and all browser logic in one long template.
- `scripts/ccusage_html_report/report.py` mixed ccusage payload normalization, pricing lookup, date inference, transcript enrichment, and final report assembly.

That shape made feature work risky because editing one area required scrolling through unrelated concerns. The refactor keeps the single-file generated HTML output, but makes the source tree easier to navigate.

## Source Layout

The HTML renderer is now a thin resource composer:

| File | Responsibility |
| --- | --- |
| `html.py` | Reads assets, embeds JSON data, returns the standalone HTML string. |
| `assets/report.html` | Static document shell and report containers. |
| `assets/report.css` | Dashboard styling. |
| `assets/report-state.js` | Initial frontend state and palette. |
| `assets/report-utils.js` | Formatting and escaping helpers. |
| `assets/report-filters.js` | Session filter setup and filter-state helpers. |
| `assets/report-charts.js` | Canvas setup, legend, tabs, bar chart, and line chart rendering. |
| `assets/report-sessions.js` | Session filtering, cards, drawer, conversation loading, and session list rendering. |
| `assets/report-summary.js` | Header stats, archive note, model pricing note, and model mix cards. |
| `assets/report-init.js` | Event binding and initial render. |

The data pipeline is now split by domain:

| File | Responsibility |
| --- | --- |
| `report.py` | Coordinates ccusage payloads, periods, sessions, pricing, totals, and final payload shape. |
| `metrics.py` | Normalizes token/cost fields, model breakdowns, buckets, and aggregate totals. |
| `pricing.py` | Fetches models.dev/LiteLLM price metadata and applies model-level cost estimates. |
| `sessions.py` | Builds session rows, transcript snippets, full conversations, titles, dates, and sort fields. |
| `dates.py` | Parses timestamps and builds ISO week labels. |

## Compatibility Notes

The generated report is still a standalone local HTML file. CSS and JavaScript are read from separate source files during generation, then embedded into the final output so users do not need to copy asset folders alongside reports.

Existing imports from `ccusage_html_report.report` are kept mostly compatible by re-exporting the helper names through imports in `report.py`. New code should prefer importing helpers from their domain modules directly.


Browser smoke verification loaded a generated sample report through a temporary localhost server. The page rendered summary stats, model mix, charts, and session cards with no current-page console errors.

## Notes

- This release is intentionally structural; it should not change report output semantics.
- Future chart or session UI work should now start in the relevant asset file instead of editing a giant Python template.
- Future data-shape work should start in `metrics.py`, `pricing.py`, `sessions.py`, or `dates.py` before touching `report.py`.
